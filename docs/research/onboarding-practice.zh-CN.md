# Reva 上手指南：离线练习与迁移入口

## 设计依据

- [HTTPie CLI](api-tools/httpie.md) 的 `--offline` 将构造请求与发送分开。它不会发出 HTTP 请求，但显式文件输入及会话仍可能产生本地副作用；Reva 借鉴的是操作分离，不照搬会话或命令输出。
- [Bruno](api-tools/bruno.md) 的 **Try** 将已保存的示例打开为临时副本，让用户试改而不覆盖原件。借鉴的是草稿隔离，不引入响应示例库、Mock 服务或线上重放。其迁移工作流区分普通单集合导入与商业整批迁移；Reva 继续走现有格式、兼容通知和确认流程，不承诺无损迁移。
- 从其他领域借鉴同一原则：代码评审先看差异再合并，支付流程先校对再提交。上手指南把低承诺练习、审查和有副作用的执行拆成独立操作。“沙箱”在这里指未提交草稿与交互边界，不是通用的进程、脚本、文件系统或网络隔离环境。

## 用户操作与边界

1. **离线预览示例 / Preview sample offline** 关闭指南，打开现有的发送前只读预览。示例是新建的独立未保存请求：`GET https://example.invalid/hello`，请求头为 `Accept: application/json`，没有认证、正文或脚本。关闭预览后可继续编辑 **示例请求 / Sample request**；再次从指南开始练习会得到新标签和请求 ID，不覆盖先前编辑。
2. **导入已有请求 / Import existing requests** 关闭指南并打开同一个导入对话框，并不自动检查、确认或保存。用户自行选择来源或粘贴内容，再点击 **检查导入**、确认兼容通知并点击 **确认导入**。取消检查或确认前退出不创建数据。粘贴 curl 或 Postman 文本走离线解析；如果用户另行选择 Swagger URL 并点击检查，现有流程会联网获取规范，不属于离线示例。
3. **完成**仍只负责保存指南完成状态；**暂时跳过**仍只关闭指南。两项新操作都不替用户标记完成，之后仍可从设置打开或重新查看指南。

`example.invalid` 是占位地址，不是可用的示例服务，也不会生成模拟响应。点开预览不会发请求、执行脚本或读取上传文件；另行点击 **发送** 则进入普通传输流程，即使地址是 `.invalid`，也可能产生 DNS、连接尝试或按传输环境经过代理。应先把地址换成自己有权使用的测试 API。预览描述的是前置脚本运行前的状态，不是完整线上报文。

## 二阶影响：用户与模块

| 领域 | 影响与约束 |
| --- | --- |
| 工作台及活动环境 | 从环境页进入设置时，练习也必须切回请求工作台才能显示预览。切换工作区不等同于取消或更换活动环境，也不清空已有请求或环境草稿。示例没有变量占位符和集合认证继承，不把当前环境的值写进草稿。 |
| 隐藏数据与可访问性 | 沿用[现有脱敏预览](pr-r4-preview.md)：请求头值、变量值及相关敏感背景应从绘制和可访问标签中隐藏，退出后恢复普通编辑界面。确认使用的作用域不要求显示值；遮盖是展示保护，不是凭据保险库。 |
| 导入审查 | 指南和常规入口必须进入同一对话框，沿用目的地、格式限制、兼容通知、显式确认和迟到结果失效规则。不维护一个绕开检查的快捷导入器，不将迁移说明视为格式兼容承诺。 |
| 设置、历史、备份与同步 | 只打开、练习、检查或取消不保存设置、集合、环境或历史，不触发备份或同步。独立且已获授权的后台任务仍按原规则完成，不因指南或预览被取消；用户随后明确保存、导入或发送时，原有持久化和同步规则仍适用。 |
| 代理与传输 | 练习与预览不调用发送器、不改变传输或代理设置；用户之后发起的网络操作仍走各自常规路径。不能把保留域名或脱敏视为阻止代理接触信息的网络策略。 |

## 三阶影响：维护成本与取舍

复用预览、导入和正常标签生命周期，避免维护第二套脱敏、兼容规则或初始草稿模型，且无需新依赖、持久化字段或迁移。但指南跨越设置、工作区和两个模态：导航门控、焦点、背景遮盖、导入异步检查或最小窗口布局变化，都可能让按钮看似可用而无法完成流程。回归通过现有 Viva headless Driver 检查中英文、明暗主题及 960×600 的按钮范围、点击和模态切换后的键盘操作；以临时目录真实存储、发送计数和已配置的同步状态验证关键副作用。它不是原生窗口像素验收，也不验证第三方服务可用性。

这次改善已有能力的可发现性，不重复实现已发布的 `reva-run` 或发送前预览（见[实现记录](implementation-results.zh-CN.md)）。[实施计划](implementation-plan.zh-CN.md) 中的秘密值 / Cookie 会话和 SSE 增量显示有各自的数据生命周期与传输验收，不塞进指南迭代；负载、契约验证、Mock 等专业任务继续优先交给专业工具，另行评估审查后导出与互操作，不将指南扩展为测试平台。

## PR 所有权与审查顺序

| PR | 范围 | 审查重点 |
| --- | --- | --- |
| 1：文案 | Settings 类型化中英文按钮及示例名称 | 两种语言语义一致，并区分预览、发送与导入确认。 |
| 2：工作台状态 | 独立示例草稿、工作区切换与现有预览／导入入口复用 | 新 ID、原有草稿和活动环境不变；无隐式发送、保存或审查。 |
| 3：指南界面 | Settings 指南按钮、模态交接和最小窗口布局 | 两个入口在最小窗口可点击；完成、跳过和重新查看仍按原规则运行。 |
| 4：验收与研究 | `internal/gui/onboarding_actions_test.go` 与本文 | 复验完整用户路径、脱敏、确认门槛和本地数据不变。 |

先分别审查文案和工作台状态，再在包含两者的分支审查指南界面。验收 PR 只叠在已验证的界面分支上；最终在完整堆栈运行 `gofmt -l .`、`go vet ./...`、`go tool viva vet ./...`、`go test ./... -count=1` 和 `git diff --check`。
